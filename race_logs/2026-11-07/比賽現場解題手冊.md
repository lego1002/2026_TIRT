# 比賽現場解題手冊

一個人比賽很緊張是正常的。這份手冊的目的，是讓你在腦袋一片空白時，還有下一步可以照著做。

> 標記說明：**[實測]** 是這台車實際驗證過的；**[待驗證]** 是合理的推測，先在家測過再帶上場。

## 出問題時先做這三步

1. **先讓車停下來，再想問題。** 取消目標，或用選單 `0` 全關。比賽計時開始後不能遠端操作，這些動作只用在開跑前或練習時。
2. **只回答兩個問題。**
   - 車子實際上有沒有在動？
   - RViz 裡的紅色掃描點有沒有貼在牆上？
3. **一次只改一件事，再跑一次。** 同時改兩件事，就算變好也不知道是哪個有效。

## 兩個問題怎麼判斷

| 車子 | 紅點 | 問題多半在 | 看哪一節 |
|---|---|---|---|
| 正常走 | 貼牆 | 沒問題，或目標和參數設定 | |
| 抖或走不動 | 貼牆 | **控制或打滑** | [車在抖、走不動](#車在抖走不動) |
| 正常走 | 離開牆 | **定位** | [位置不對](#rviz-上的位置不對) |
| 抖或走不動 | 離開牆 | **先修定位**，再看控制 | [位置不對](#rviz-上的位置不對) |

## 依症狀處理

### 車在抖、走不動

這次比賽的主要症狀：車子只跑一點點，反覆左右移動，輪子沒有空轉。訊息通常是 `Failed to make progress`，也就是 15 秒內離開原點不到 10 公分，來回移動不會被算成前進。

1. **先分清楚是哪一種：**
   - 車子左右來回：控制器在修正，或定位在跳，繼續看第 2 步。
   - 輪子在轉、車不動：打滑，先降加減速。
   - 輪子不轉：確認遙控有沒有關，再看選單 `6`。
2. **看定位有沒有跳：** 盯著 RViz 的車子。實際車身來回，RViz 位置也同步，比較像控制器；車沒怎麼動，RViz 位置卻在跳，就是定位。
3. **控制器來回時，先降橫移 [待驗證]：** 改 `config/nav2_params.yaml`，把 `FollowPath` 的 `max_vel_y`、`min_vel_y` 和 `velocity_smoother` 的 y 軸速度一起降，例如從 0.14 降到 0.07。然後選單 `0`，再選 `4`。
4. **還是來回，再降加減速 [待驗證]：**

   ```yaml
   max_accel: [0.6, 0.6, 2.0]    # 原本 [1.5, 1.5, 3.0]
   max_decel: [-1.0, -1.0, -3.0] # 原本 [-2.0, -2.0, -3.0]
   ```

速度要在 `FollowPath`、`velocity_smoother`、`behavior_server` 一起看，只改一個可能沒有效果。細節在 `notes/nav2_tuning.md`。

### 地圖飄掉、牆變雙線

- **建圖時不要用 `a/d` 原地轉 [實測]：** 靠直走和橫移完成掃描，就算打滑，牆也比較穩。
- **一定要轉就放慢：** 用 `e` 降轉向速度，轉完停一下再走。
- **圖已經歪了就重建：** 通常比在壞地圖上調參數省時間，這次第 3 次建圖才成功也沒關係。

### RViz 上的位置不對

- **OK（READY）不等於位置正確：** 它只表示定位結果很集中，還是要看紅點有沒有貼牆。
- **紅點貼牆：** 不用做 Estimate，直接跑。
- **紅點離開牆：** 用 2D Pose Estimate 點車子的真實位置和方向，再選單 `9`。
- **搬過車 [實測]：** 手搬會讓陀螺儀短暫算錯，放下後等 3 分鐘再標位置。
- **想看數字：** 跑 `python3 tools/scan_match_check.py`。如果它找得到明顯更好的位置，就是定位偏了，地圖本身沒問題。

### 出現 `failed to generate a valid path`

1. 先看紅點有沒有貼牆。定位偏掉時，規劃也會跟著失敗。
2. 跑 `python3 tools/costmap_check.py`，看車子所在的位置能不能走、能走到多大範圍。
3. 只有地圖真的太窄，才用選單 `r` 調安全圈。**比賽前記得確認選單顯示的是想要的設定。**

### 開導航後一直沒好

平常約 20～40 秒。**超過 60 秒就不要再等 [實測]：** 選單 `0` 全關，再選 `4`。這次這樣做就恢復了。

### 車子一抖一抖、跑得特別慢

**先確認鍵盤遙控關了 [實測]。** 遙控開著會一直送「速度 0」，和導航搶控制。2026-11-06 測到同一段路從 28 秒變 57 秒。

### 什麼都不對，又不知道從哪開始

跑選單 `6` 健康檢查，一次看供電、電池、光達和里程。這幾項都正常，就回到前面的兩個問題。

## 這些紅字可以先不管

| 訊息 | 什麼時候出現 |
|---|---|
| `Unable to start transition`、`No transition matching` | 關閉導航時 |
| `Failed to get result for follow_path in node halt` | 取消目標時 |
| `process has died [... exit code -9]` | 全關時強制關掉導航 |
| `No goal checker was specified` | 導航開始時 |
| `queue is full`（只有一次） | SLAM 剛啟動時 |
| `Behavior Tree tick rate exceeded`（偶爾幾次） | 救援切換時 |

**判斷原則：** 看它有沒有一直重複、車子有沒有異常。只出現一次、車子也正常，就先繼續。

## 開跑前檢查（約 1 分鐘）

- [ ] 鍵盤遙控已經關掉
- [ ] 紅點貼在牆上
- [ ] 中繼區和終點都排進航點，再開跑（開跑後不能再操作）
- [ ] 選單的安全圈是想要的設定
- [ ] 手機開始拍影片
- [ ] 開始錄資料（見下一節）

## 讓下次分析得出原因

這次最可惜的是沒有錄到車子的位置和速度。下次**開跑前**做這兩件事：

1. **手機拍全程。** 最簡單也最有用，可以看出左右移動的幅度和頻率，也能看出輪子有沒有空轉。
2. **錄導航資料：** 選單 `8` 進 tmux 的 `shell` 視窗，執行：

   ```bash
   python3 tools/nav_record.py ~/run1.jsonl 180
   ```

   `180` 是錄 180 秒。這個工具會掉一些樣本，可以看趨勢，不適合算頻率。

## 平常可以怎麼準備

比賽的緊張，很大一部分來自第一次碰到某種狀況。可以在家先把狀況碰過一輪：

- **模擬滑的地面：** 這次在家地板抓得住，所以沒測出打滑問題。找光滑的地面來測。
- **把距離拉長：** 家裡單趟最遠 2.63 m，比賽要跑 3.8～4.3 m。至少排練一次 4 m 以上。
- **完整排練：** 計時 30 分鐘，從開機、建圖、存圖、導航一路做完，中途故意全關重開一次。
- **準備一組保守參數：** 先在家驗證一組慢但穩的設定，現場不順就直接換，不用臨時想。
- **先訂好時間分配：** 例如建圖最多試到第 15 分鐘，最後 5 分鐘不再改任何參數。

## 這場比賽學到的事

1. **在家能跑，不代表換了地面也能跑。** 測試環境要盡量貼近比賽場地。
2. **一次試一個變數很有效。** 不用 `a/d` 地圖就穩，是這場最有價值的發現，就是這樣試出來的。
3. **沒有紀錄就只能猜。** 影片和資料開跑前就要開著。
4. **紅字不一定是壞事。** 先看它有沒有重複，以及車子實際的表現。
5. **卡住時全關重開是合理的選擇。** 比賽時先把車救回來，原因賽後再查。
